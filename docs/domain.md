# 领域模型（提案）

> 状态：**草案，未定稿。** 这是根据「多类资产净值追踪」这一句话推导出来的最小模型，
> 目的是让实现有个起点。产品细节确定后需要修订。

## 设计前提

**快照式，不是流水式。** 用户不录入交易，而是定期回答"这项资产现在值多少"。
这决定了整个数据模型的形状：核心表是 (资产 × 时间 → 估值)，不是交易账本。

## 核心实体

### Asset — 一项资产或负债

用户持有的一个东西。一次性创建，之后基本不变。

- `id`
- `name` — 用户自己起的名字，如"招行储蓄卡"、"公司期权"
- `category` — 见下方分类
- `currency` — 该资产的计价币种（如 CNY / USD / HKD）
- `isLiability` — 负债标记。房贷、车贷、信用卡欠款算负债，在净值里做减项
- `quoteSymbol` — 可选。若这项资产能自动取价（股票代码、基金代码、币种），存在这里
- `quantity` — 可选。持有份额/股数。有 symbol 时用「份额 × 单价」算市值，否则用户直接填市值
- `archivedAt` — 可选。已卖出/已结清的资产归档而非删除，历史净值曲线要保持完整

### Snapshot — 某时刻的估值

**不可变、只追加。** 修正历史不是原地改，是插入一条新记录并让旧的失效。
这样净值曲线的历史永远可复现。

- `id`
- `assetId`
- `asOf` — 估值时点
- `valueMinor` — 该资产在其自身币种下的市值，**整数最小单位**（分），见下方
- `source` — `MANUAL` / `QUOTE`（自动拉的行情）/ `DERIVED`
- `recordedAt` — 录入时间，和 `asOf` 区分开（可以补录上个月的数据）

### FxRate — 汇率

- `base` / `quote` / `asOf` / `rate`

折算历史净值时要用**当时的汇率**，不是今天的汇率。否则汇率波动会污染历史曲线，
让用户看到自己从没经历过的涨跌。

### 派生：NetWorth 时间序列

不是表，是查询结果。

```
某时点净值 = Σ(资产快照市值 × 当期汇率) - Σ(负债快照市值 × 当期汇率)
```

计算时的取值规则：某资产在目标时点没有快照，就取**该时点之前最近的一条**
（净值是存量概念，上次估值继续有效），而不是当它不存在。

## 资产分类（初版）

现金存款、股票、基金、债券、加密货币、房产、车辆、贵金属、应收款、其他；
负债侧：房贷、车贷、消费贷、信用卡。

分类主要用于饼图/构成分析和默认取价方式，不影响净值算法本身。

## 金额表示：绝不用 Double

全程 `Long` 存**最小货币单位**（分）。理由：净值是大量数字连加，浮点误差会累积并被放大，
而这个 App 的全部价值就在于那个总数的可信度。

份额（`quantity`）可能需要小数（基金份额、加密货币），用定点表示：
存 `Long` + 固定小数位，或用字符串存精确十进制，**不要用 Double**。

## 时间处理

- 存储用 `kotlin.time.Instant`（UTC）
- 展示和"按日/按月分组"用用户本地时区的 `LocalDate`
- 快照的 `asOf` 语义是"这一天结束时的估值"，跨时区要一致

## 待定问题

这些需要产品侧拍板，实现前先问：

1. 用户多久更新一次快照？要不要提醒？
2. 自动取价的资产，是每次打开 App 就刷新，还是每天定时生成一条快照？
   （关系到快照表的增长速度）
3. 手动改了自动取价资产的市值，下次自动刷新要不要覆盖？
4. 基准币种是单一全局设置，还是可以切换查看？
5. 归档资产在历史曲线里怎么表现 —— 卖出当天归零，还是曲线截断？
